# REVIEW.md

Review of the starter `app/main.py` (line numbers refer to the starter as received). Every defect below is
covered by a test in `tests/`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How I fixed it |
|---|---|---|---|---|
| 1 | `health`, l.73 | Always returns 200; never talks to MongoDB. | Stop `mongod`, `GET /health` still says `ok`; the grader's readiness poll passes against a dead database. | `db.command("ping")` inside try/except → 503 with `{"detail": ...}`; also (re)creates indexes once the DB answers. |
| 2 | `MongoClient(...)`, l.22 | Client is not `tz_aware`, so every datetime read back is **naive**; default 30 s server-selection timeout. | Any arithmetic between a stored `punch_in` (naive) and an aware IST shift instant raises `TypeError: can't subtract offset-naive and offset-aware datetimes` → 500 on punch-out. `/health` hangs 30 s when Mongo is down. | `MongoClient(uri, tz_aware=True, tzinfo=UTC, serverSelectionTimeoutMS=5000)`. All instants are aware UTC inside the process. |
| 3 | `compute_late_minutes`, l.33–37 | (a) The shift start is anchored on `punch_in`'s own calendar day in whatever zone `punch_in` is in (naive/local), not on the IST attendance date — wrong near midnight and for overnight shifts. (b) `int(seconds/60) > 10` tests *minutes*, so 09:40:01–09:40:59 → `int(10.0x)=10` → **not late**, but R2 says 09:40:01 is late with 10. | Shift 09:30, punch-in 09:40:30 → starter returns 0, contract says 10. Punch-in 00:30 IST for a 22:00 shift → anchored on the wrong day. | Anchor on `date` (IST) via `ist_instant(date, shift_start)`; compare **seconds** `> 600`, then floor to minutes. |
| 4 | `compute_work_hours`, l.41 | `round()` is banker's rounding on a binary float, not half-up. | 9:00 → 11:40:30 is 2.675 h: `round(2.675, 2)` = 2.67, R4 wants 2.68. 9:00:27 → 0.0075 h → 0.0 instead of 0.01. | `Decimal(seconds) / 3600` quantized with `ROUND_HALF_UP`. |
| 5 | `compute_overtime`, l.44–47 | (a) Missing the "only if ≥ 30" rule — every minute after shift end is overtime. (b) Overnight shifts: `shift_end` is placed on the attendance date, but it falls on the **next** day → ~24 h of phantom overtime. (c) `date_str` is parsed with `fromisoformat` + `replace(tzinfo=IST)` fine, but then subtracted from a naive `punch_out` → `TypeError`/500 (see #2). | Punch-out 18:35 for an 18:30 shift → 5 instead of 0. Night shift 22:00–06:00 punched out 06:40 → ~1480 instead of 40. | Shift end anchored on `date + 1 day` when `shift_end <= shift_start`; floor minutes; return 0 when < 30. |
| 6 | `EmployeeIn` / `PunchInIn`, l.52–68 | No validation at all: `emp_code` pattern, name/email/department lengths, `HH:MM` shape, `shift_start != shift_end`, `joined_on` as a real date; `punched_at: Optional[int]` is a **lax** int (accepts `1783312500000.0`, `"1783312500000"`, and seconds-looking values); `status: str` accepts `ABSENT`, `LEAVE` or `banana`. | `POST /employees` with `shift_start == shift_end`, `joined_on: "2026-02-30"` or `emp_code: "X"` → 201. `punched_at: 1783312500` (seconds) → record dated 1970. `status: "ABSENT"` creates an absent record with a punch time. | Pydantic v2 models with patterns/lengths, `StrictInt` bounded to the epoch-ms range, `PresenceStatus` enum, cross-field validator for the shifts, real-date check for `joined_on`. |
| 7 | `create_employee`, l.79–83 | (a) Check-then-insert: two concurrent creates with the same `emp_code` both pass the `find_one` and both insert → duplicates. (b) No unique index exists, so nothing stops it. (c) `created_at = datetime.now()` is the **server's local time, naive**; stored as if UTC. (d) `created_at` is returned as an ISO string (FastAPI serialises the datetime), contract wants epoch ms. | 12 parallel `POST /employees` → twelve 201s. Response shows `"created_at": "2026-07-06T09:28:00"`. | Unique index on `emp_code` created at startup; `insert_one` and catch `DuplicateKeyError` → 409; `datetime.now(UTC)`; serialiser converts to epoch ms. |
| 8 | `list_employees`, l.93 | `skip = page * page_size` skips a whole page: page 1 starts at record 21. | 3 employees, `GET /employees` → empty `items`. | `skip = (page - 1) * page_size`. |
| 9 | `list_employees`, l.94 | `total = count_documents({})` ignores the department filter (R10). | `?department=Sales` with 2 of 3 employees → `total: 3`. | Count the same filter used for `items`. |
| 10 | `list_employees`, l.95 | No sort — contract says `emp_code` ascending; order is insertion order and changes under updates. | Insert EMP0003 before EMP0001 → listed in that order. | `.sort("emp_code")` served by the unique index (or `(department, emp_code)` when filtered). |
| 11 | `list_employees` / `list_attendance` params | `page` / `page_size` unbounded. | `page=0` → negative skip → `ValueError` → 500; `page_size=100000` → unbounded result. | `Query(1, ge=1)` and `Query(20, ge=1, le=100)` → 422. |
| 12 | `punch_in`, l.101 | Unknown employee is not checked; `emp["shift_start"]` on `None` → `TypeError` → 500 instead of 404. | `POST /attendance/punch-in {"emp_code":"EMP9999"}` → 500. | `get_employee_or_404`. |
| 13 | `punch_in`, l.102–103 | (a) `datetime.fromtimestamp(ms/1000)` keeps milliseconds (R1 says truncate to seconds) and produces a **naive local-time** datetime. No `date_from > date_to` → 422; no date-format validation; `status` not restricted to the enum. | 100k records: hundreds of ms and ~100 MB per page request; `?date_from=2026-07-31&date_to=2026-07-01` → 200 with empty list; `?status=SICK` → 200. | `find(...).sort([date desc, emp_code asc]).skip().limit()` with an index hint; `count_documents` for `total`; validation → 422; `status: Status` enum. |
| 17 | whole file | No indexes are ever created; the grader's database has only `_id`. | `/admin/explain/*` would show COLLSCAN; every lookup by `emp_code` scans the collection. | `ensure_indexes()` at startup (lifespan) and again from `/health`, idempotent by name. See DECISIONS.md. |
| 18 | whole file | No `lifespan`/shutdown: client never closed; errors from PyMongo surface as 500. | Mongo down mid-run → 500s. | Lifespan closes the client; a `PyMongoError` handler returns 503. |

**Looked at and judged fine**

* `load_dotenv()` without `override` — correct: environment variables already set take priority over `.env`, as required. Kept (with explicit `override=False` for readability).
* Synchronous PyMongo inside `def` endpoints — fine: FastAPI runs them in a thread pool and PyMongo is thread-safe with a connection pool, so concurrent requests are served concurrently. Kept rather than switching to Motor.
* `compute_late_minutes` returning 0 for an early punch-in (negative difference) — correct; kept the behaviour.
* Reusing the helper *signatures* — not kept: every helper takes the employee and the attendance date now, because every rule is anchored on the IST attendance date, not on the punch instant's own day.
